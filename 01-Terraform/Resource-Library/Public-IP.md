# 🌐 Terraform Resource: azurerm_public_ip

> "A Public IP is the front door of your house on the Internet. It gives the outside world an address to reach your Azure resources."

---

## 📖 Before You Read

Before diving into this Terraform resource, make sure you understand:
- What a **Provider** is in Terraform — see [[03-Providers]]
- What a **Resource Block** is — see [[04-Resources]]
- The difference between **Static** and **Dynamic** IP allocations in networking.

---

## 1. 🤔 What is `azurerm_public_ip`?

### 🤔 What is it?

In Azure, a **Public IP address** is a resource that provides inbound access to Azure resources from the Internet and outbound access from Azure resources to the Internet. 

In Terraform, the `azurerm_public_ip` block allows you to request and configure a Public IP address that you can later attach to resources like Virtual Machines (via a Network Interface), Load Balancers, or Application Gateways.

> 📁 **Real-World Analogy:**
> Imagine a large corporate office building (your Azure Virtual Network). The building has many internal offices (Virtual Machines), but they only have internal phone numbers (Private IPs). If you want an office to receive calls directly from the outside world, you have to buy a public phone number from the phone company and route it to that specific office.
>
> An `azurerm_public_ip` is exactly like that public phone number.

---

## 2. 🧠 Why do we need it?

By default, Azure resources (like VMs) created inside a Virtual Network only get Private IPs. They cannot be reached from the Internet.
You need a Public IP if you want to:
1. **SSH or RDP** into a Virtual Machine from your home computer.
2. Expose a **Web Server** to the public internet.
3. Serve traffic through an Internet-facing **Load Balancer**.

---

## 3. ⚙️ How does it work?

The `azurerm_public_ip` block typically requires:
1. `name`: What to call this IP resource in Azure.
2. `resource_group_name`: Which folder (Resource Group) to put it in.
3. `location`: Which Azure datacenter it lives in (usually the same as the resource it attaches to).
4. `allocation_method`: Either `Static` (the IP never changes) or `Dynamic` (the IP can change if the attached resource stops/starts).

---

## 4. 💡 Real Example (Line-by-Line)

Here is exactly how you write the Terraform code to create a Public IP, broken into best-practice files.

### `variables.tf` (The Inputs)
```hcl
variable "public_ip_name" {
  type        = string
  description = "The name of the public IP."
  default     = "pip-myapp-prod-eus"
}

variable "location" {
  type        = string
  description = "The Azure region."
  default     = "eastus"
}

variable "resource_group_name" {
  type        = string
  description = "The name of the resource group."
}
```

### `main.tf` (The Actual Resource)
```hcl
# ---- THE RESOURCE BLOCK ----
# "azurerm_public_ip" is the official Microsoft resource type.
# "main" is our local Terraform reference name.
resource "azurerm_public_ip" "main" {
  
  # 1. The Azure resource name
  name                = var.public_ip_name
  
  # 2. Where the IP exists
  location            = var.location
  
  # 3. The Resource Group it belongs to
  resource_group_name = var.resource_group_name
  
  # 4. Allocation Method (Static vs Dynamic)
  allocation_method   = "Static"
  
  # Optional but recommended for standard production workloads
  sku                 = "Standard"
}
```

### `outputs.tf` (The Results)
```hcl
# Output the ID so we can attach it to a Network Interface later
output "public_ip_id" {
  description = "The unique Azure ID of the Public IP."
  value       = azurerm_public_ip.main.id
}

# Output the actual IP address generated by Azure!
output "public_ip_address" {
  description = "The actual IPv4 address assigned by Azure."
  value       = azurerm_public_ip.main.ip_address
}
```

## 5. ⚠️ Common Mistakes Beginners Make

1. **Confusing Static vs Dynamic:** Using `Dynamic` allocation means the IP address isn't actually generated until it is attached to a running resource. If you try to output `ip_address` on a dynamically allocated IP that isn't attached to anything, Terraform might return nothing or an empty string!
2. **SKU Mismatches:** If you plan to attach a Public IP to a Standard Load Balancer, the Public IP's `sku` MUST be set to `Standard`. By default, older Terraform code might use `Basic`, which will cause an error when you try to attach them.
3. **Forgetting Network Security Groups:** Just attaching a Public IP to a VM doesn't mean you can access it. You still need a Network Security Group (NSG) to allow inbound traffic on ports like 22 (SSH) or 80 (HTTP).

---

## 6. 🎯 Key Takeaway

The `azurerm_public_ip` is your gateway from the internet into your Azure resources. Always plan your `allocation_method` carefully, and prefer `Static` with the `Standard` SKU for production workloads to ensure stability and compatibility with load balancers and availability zones.

## 7. ❓ Beginner FAQ

**Q1: Does a Public IP cost money?**
> Yes, Azure charges a small hourly fee for reserved Static Public IPs and for Dynamic Public IPs when they are running. 

**Q2: How do I attach it to a Virtual Machine?**
> You don't attach it directly to the VM resource! Instead, you attach the Public IP ID to the **Network Interface (NIC)** resource, and then attach the NIC to the VM.

**Q3: Can I assign a domain name (like www.myapp.com) directly to this IP using Terraform?**
> Yes! You can use the `domain_name_label` argument inside the `azurerm_public_ip` block to get a Microsoft-provided DNS name like `myapp.eastus.cloudapp.azure.com`. To use a custom domain, you would map it using a DNS registrar (like Route53 or Azure DNS) pointing to the output IP address.
